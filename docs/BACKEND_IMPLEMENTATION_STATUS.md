## Migrations and compatibility

- `0003_bookkeeping_and_private_workflows.py`: 20 additive tables; core accounting remains typed, private evidence/jobs/support metadata remain owner-scoped.
- `0004_legacy_ledger_and_phone_accounts.py`: backfills existing expense IDs into one canonical ledger without changing old expense amounts/dates/notes; creates only necessary real-user taxi businesses; nullable email supports phone-only users; incompatible downgrade refuses to discard accounts.
- `0005_explicit_share_overrides.py`: preserves prior explicit work-share decisions and distinguishes inherited defaults for reasoned open-year policy corrections.

The schema has 28 total tables, reusing the original eight. The proposed 46-table design was consolidated deliberately: versioned profile aggregates/employments/preferences in `book_profiles`; stable small catalogs and source/rule IDs in code; statement payout payloads in the statement snapshot; separate typed canonical postings in `transactions`; integration/consent/extraction envelopes in `support_records`; history in `book_mutations`; private file bytes in PostgreSQL. Ownership is enforced at every service reference and write, rather than adding duplicate client-controlled ownership inputs. These are documented adaptations of a proposal, not claims of implementing 46 independent tables.

The `/api/v1` prefix, established `detail` error envelope, existing password form login, provider challenge exchange, revocable device sessions and legacy offset paging stay compatible. Tax/financial fields are integers or Decimal-derived strings. No database deletion/reset was used. Financial/history reversal preserves evidence; new exports/summaries do not create a second ledger.

2. **Files/OCR/PDF:** configure reachable ClamAV and select a real OCR provider with privacy/retention terms; provide representative Uber/Bolt PDF exports and expected accounting/date/refund cases. Built-in CSV is usable now; native platform PDFs are not.

The [current official Self Employment Business API page](https://developer.service.hmrc.gov.uk/api-documentation/docs/api/service/self-employment-business-api/5.0), checked 27 October 2026, warns about production credential availability for new 2026–27 quarterly-update products. Confirm an applicable access/recognition path before enabling real sends. No production acceptance is fabricated.
5. **Assistant/accountant/notifications:** choose an assistant provider and approved context/consent policy, verified accountant recipient/delivery service, and any push delivery provider. The current backend supports stored consented requests, in-app reminders and explicit failed external outcomes. Device permissions, calendar writes and camera/file acquisition are client work.
